
COMMON ISSUES & SOLUTIONS
=========================

Issue 1: Users Can't Login After Deployment
Solution:
- Users need to re-login to get new JWT token with plantId
- Clear browser cookies
- Try incognito/private browsing mode

Issue 2: Store Users See No Data
Solution:
- Verify user has plantId assigned in database
- Check JWT token includes plantId
- Verify store filtering logic in API routes

Issue 3: Admin Can't See All Data
Solution:
- Verify canAccessAllStores() function works
- Check Admin role in JWT token
- Verify no hardcoded plantId in queries

Issue 4: Performance Degradation
Solution:
- Check plantId index exists
- Analyze slow queries
- Optimize database queries
- Add caching if needed

Issue 5: Cross-Store Data Leakage
Solution:
- Immediately investigate
- Check all API routes for missing filters
- Review repository methods
- Audit recent changes

VERIFICATION QUERIES
====================

Run these queries to verify deployment:

Query 1: Check User Store Assignments
```sql
SELECT 
  role,
  COUNT(*) as user_count,
  COUNT(CASE WHEN plantId IS NULL THEN 1 END) as without_store,
  COUNT(CASE WHEN plantId IS NOT NULL THEN 1 END) as with_store
FROM "User"
GROUP BY role;
```

Query 2: Check Product Distribution
```sql
SELECT 
  p.name as store_name,
  COUNT(pr.id) as product_count
FROM "Plant" p
LEFT JOIN "Product" pr ON pr.plantId = p.id
GROUP BY p.id, p.name
ORDER BY product_count DESC;
```

Query 3: Check Schedule Distribution
```sql
SELECT 
  p.name as store_name,
  COUNT(s.id) as schedule_count
FROM "Plant" p
LEFT JOIN "Schedule" s ON s.plantId = p.id
GROUP BY p.id, p.name
ORDER BY schedule_count DESC;
```

Query 4: Check Orphaned Records
```sql
-- Products without store
SELECT COUNT(*) as orphaned_products
FROM "Product"
WHERE plantId IS NULL;

-- Schedules without store
SELECT COUNT(*) as orphaned_schedules
FROM "Schedule"
WHERE plantId IS NULL;
```
